# 责任链模式（Chain of Responsibility Pattern）

## 模式简介

责任链模式属于**行为型设计模式**，使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。将这些对象连成一条链，沿着这条链传递请求，直到有一个对象处理它为止。

## 模式结构

```
                         ┌────────────────────────┐
                         │  ApprovalHandler        │
                         │  (抽象处理者)            │
                         ├────────────────────────┤
                         │ - name                  │
                         │ - nextHandler           │
                         │ + setNext(handler)      │
                         │ + handle(amount)        │
                         │ # passToNext(amount)    │
                         └───────────┬────────────┘
                                     │
                  ┌──────────────────┼──────────────────┐
                  │                  │                   │
        ┌─────────┴────────┐ ┌──────┴───────┐ ┌────────┴───────┐
        │ TeamLeaderHandler │ │ManagerHandler│ │DirectorHandler │
        │ 组长（≤1000元）   │ │经理（≤1万元） │ │总监（≤5万元）  │
        └──────────────────┘ └──────────────┘ └────────────────┘

请求传递方向：组长 ──> 经理 ──> 总监 ──> 驳回
```

## 角色说明

| 角色 | 类名 | 说明 |
|------|------|------|
| 抽象处理者 | `ApprovalHandler` | 定义处理请求的接口，持有下一个处理者的引用 |
| 具体处理者A | `TeamLeaderHandler` | 组长，可审批 1000 元以下的请求 |
| 具体处理者B | `ManagerHandler` | 经理，可审批 10000 元以下的请求 |
| 具体处理者C | `DirectorHandler` | 总监，可审批 50000 元以下的请求 |
| 演示入口 | `ChainOfResponsibilityDemo` | 演示如何构建责任链并发起请求 |

## 使用示例

```java
// 构建审批链
ApprovalHandler teamLeader = new TeamLeaderHandler("张三");
ApprovalHandler manager = new ManagerHandler("李四");
ApprovalHandler director = new DirectorHandler("王五");
teamLeader.setNext(manager).setNext(director);

// 发起审批，请求会自动沿链传递
teamLeader.handle(5000);
```

## 适用场景

1. **多级审批流程**：费用报销、请假审批等逐级上报的场景
2. **过滤器/拦截器链**：Servlet Filter、Spring Interceptor
3. **事件冒泡机制**：GUI 事件从子组件向父组件传递

## 优缺点

### 优点
- **解耦**：请求发送者无需知道哪个对象会处理请求
- **灵活**：可以动态增减处理者或调整链的顺序
- **单一职责**：每个处理者只关心自己能处理的范围

### 缺点
- **不保证被处理**：请求可能到达链尾仍无人处理
- **调试困难**：链较长时不易追踪请求的传递过程
- **性能开销**：请求可能经过多个处理者才被处理
