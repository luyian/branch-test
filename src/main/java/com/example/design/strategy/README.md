# 策略模式（Strategy Pattern）

## 模式简介

策略模式属于**行为型设计模式**，定义一系列算法，将每个算法封装起来，并使它们可以互相替换。策略模式让算法独立于使用它的客户端而变化。

## 模式结构

```
┌─────────────────┐       ┌──────────────────────┐
│   PayContext     │──────>│   <<interface>>       │
│   (上下文)       │       │   PayStrategy         │
│                 │       │   (策略接口)            │
│ - payStrategy   │       ├──────────────────────┤
│ + executePayment│       │ + pay(amount)         │
│ + setPayStrategy│       │ + getPayType()        │
└─────────────────┘       └──────────┬───────────┘
                                     │
                    ┌────────────────┼────────────────┐
                    │                │                │
           ┌───────┴──────┐ ┌──────┴───────┐ ┌─────┴──────────┐
           │ AliPayStrategy│ │WechatPay     │ │BankCardPay     │
           │ (支付宝)      │ │Strategy      │ │Strategy        │
           │              │ │(微信支付)     │ │(银行卡支付)     │
           └──────────────┘ └──────────────┘ └────────────────┘
```

## 角色说明

| 角色 | 类名 | 说明 |
|------|------|------|
| 策略接口 | `PayStrategy` | 定义所有支付方式的统一行为规范 |
| 具体策略A | `AliPayStrategy` | 支付宝支付的具体实现 |
| 具体策略B | `WechatPayStrategy` | 微信支付的具体实现 |
| 具体策略C | `BankCardPayStrategy` | 银行卡支付的具体实现 |
| 上下文 | `PayContext` | 持有策略引用，负责调用策略方法 |
| 演示入口 | `StrategyPatternDemo` | 演示如何使用策略模式 |

## 使用示例

```java
// 创建上下文，指定初始策略
PayContext context = new PayContext(new AliPayStrategy());
context.executePayment(99.9);

// 运行时切换策略
context.setPayStrategy(new WechatPayStrategy());
context.executePayment(199.0);
```

## 适用场景

1. **多种算法可互换**：系统中有多种算法或行为，需要动态选择
2. **避免多重条件判断**：替代大量的 `if-else` 或 `switch-case`
3. **算法需要独立扩展**：新增策略无需修改已有代码，符合开闭原则

## 优缺点

### 优点
- **开闭原则**：新增策略只需实现接口，无需修改现有代码
- **避免条件语句**：消除复杂的条件判断逻辑
- **运行时切换**：可以在运行时动态切换算法
- **单一职责**：每个策略类只负责一种算法

### 缺点
- **类数量增加**：每种策略都需要一个类
- **客户端需了解策略差异**：客户端需要知道有哪些策略可选
